Product Requirement Document (PRD): Lightweight Live Polling App1. Overview & ObjectiveA lightweight, real-time audience polling application built specifically for small groups (up to 30 participants). The platform allows a Presenter to host live multiple-choice quiz/poll sessions and an Audience to join seamlessly via a room code without account creation.2. Key Target Audience & ScaleGroup Size: 1–30 concurrent connections per session.Primary Users: Team leads, educators, meeting facilitators.Core Value: Zero friction, zero paywalls for small groups, sub-second latency synchronization.3. User Roles & Core Workflows3.1 Presenter (Host)Creates a live room session with a set of pre-configured or quick questions.Controls the room state (starting the session, advancing questions, revealing live results).Displays a dedicated view designed for project screen / video call presentation.3.2 Audience (Participant)Joins a live room using a 6-digit Room Code or direct URL/QR Code.No signup/login required.Views current active question options and submits responses in real time.4. Feature Requirements & User Interfaces4.1 Presenter View (/host/:roomId)Lobby Stage:Displays 6-digit Room Code and QR Code.Shows real-time count of connected participants."Start Poll" button.Active Question Stage:Displays current question text, timer/countdown (optional), and live vote count indicator.Options to advance: "Reveal Results" and "Next Question".Results Stage:Animated bar chart / visual response distribution showing real-time vote totals per option.End Session Stage:Final summary report of total responses per question.4.2 Audience View (/join and /play/:roomId)Join Screen (/join):Input field for 6-digit Room Code + Optional Nickname.Waiting Room:Friendly state indicating session hasn't started yet ("Waiting for host...").Active Question Screen:Color-coded/large touchable buttons corresponding to question choices (e.g., Option A, B, C, D).Immediate visual disabled state upon clicking ("Vote Submitted!").Result Screen:Real-time confirmation showing whether their vote was recorded and the final aggregate distribution when revealed by the host.5. Technical Architecture & Data Model5.1 Tech StackFrontend: React / Vue / Svelte with Tailwind CSS for mobile-first layout.Backend: Node.js (Express) with Socket.IO (or WebSockets).Storage: In-Memory Javascript Map/Object (per room) + optional local SQLite/JSON persistence for session history.5.2 Socket Events MatrixEvent NameDirectionPayloadDescriptioncreate_roomClient $\rightarrow$ Server{ questions: [...] }Host creates room session.join_roomClient $\rightarrow$ Server{ roomId, nickname }Audience joins room by code.room_state_updateServer $\rightarrow$ Client{ status, currentQuestion, votes }Broadcasts active state to all devices.submit_voteClient $\rightarrow$ Server{ roomId, questionId, optionIndex }Audience submits a response.host_actionClient $\rightarrow$ Server{ roomId, action: 'START'|'NEXT'|'REVEAL' }Presenter controls current state.6. 7. Out of Scope for MVPUser account registration or OAuth login.Complex gamification systems (points, speed bonuses, streaks).Long-term persistent database infrastructure.Audio tracks or embedded sound effects.8. Success MetricsSub-500ms Synchronization: Audience screens update instantly when host advances slides or reveals responses.Zero Dropouts: 30 concurrent socket connections stay stable throughout a 30-minute session.Frictionless Onboarding: Audience members join and start voting in under 5 seconds.
